# Privacy, Ethics & Security Policy: Offline Ofrenda Keeper

**Día de los Muertos** is an intimate, sacred tradition of remembrance. Family photographs, voice recordings of deceased loved ones, and personal grief stories represent some of the most sensitive personal data a family possesses.

Offline Ofrenda Keeper was engineered from its first line of code with strict architectural privacy guarantees.

---

## 1. Zero Cloud Transmission & Airplane Mode Operation

- **100% Local Inference:** Speech transcription (`faster-whisper`), speech synthesis (`Kokoro-82M`), tone-colour transfer (`OpenVoice V2`), and remembrance generation (`Ollama` or fallback templates) run exclusively on your local computer's CPU.
- **No Third-Party APIs:** Zero data is transmitted to OpenAI, Google, ElevenLabs, Amazon, or any external cloud provider.
- **Airplane Mode Capable:** Once model weights are locally cached in `~/.cache/huggingface`, you can disconnect Wi-Fi or enable Airplane Mode. The application functions completely without an internet connection.
- **Zero Telemetry:** The application contains zero analytics, tracking cookies, remote font imports, or telemetry pixels.

---

## 2. Affirmative Family Consent Framework

Recreating the voice of a deceased relative carries profound emotional and ethical sensitivity. The system enforces strict safeguards against unauthorized likeness replication:

1. **Mandatory Affirmative Confirmation:**  
   The voice recreation endpoint (`POST /api/ofrendas/{id}/voice/convert`) strictly rejects requests unless the client submits:
   - `confirmed_permission: true`
   - Non-empty `authorized_by` string identifying the responsible family member.
   Missing or false consent immediately returns `HTTP 400 Bad Request`.
2. **Local Consent Audit Trail:**  
   Consent records are saved locally under `data/ofrendas/{id}/voice/reference_meta.json`, recording the timestamp, authorizer name, and confirmation status.
3. **Deception Prevention:**  
   The system strictly separates authentic recordings (*"In their own words"*) from synthetic speech (*"AI Voice Reading of Remembrance"*). The application never asserts or implies that the synthesized sentences were spoken by the deceased.

## 3. Audio Watermarking: Implementation & Technical Limitations

### Implementation
Synthetic audio generated by the Voice Studio is stamped via `app/voice/watermark.py` with standard **RIFF INFO metadata chunks**:
- `IART`: `Offline Ofrenda Keeper (AI-Generated Voice Recreation)`
- `INAM`: `AI Remembrance Recreation for {name}`
- `ICMT`: `Simulated memorial voice recreation. Not spoken by the deceased. For family ofrenda remembrance only. Authorized by: {authorizer}.`
- `ISFT`: `Offline Ofrenda Keeper (kokoro-openvoice)`

### Technical Limitations & Honest Disclosures
- **Container Tag Only:** The watermark is a structural RIFF metadata chunk within the WAV header, **not** an inaudible acoustic frequency-domain watermark embedded into the PCM audio samples.
- **Easily Stripped by Transcoding:** If the WAV file is transcoded, compressed to MP3/AAC, or uploaded to platforms that re-encode audio (e.g. YouTube, WhatsApp, TikTok), the RIFF INFO chunks are typically discarded by the encoder.
- **No Proof of Legal Consent:** Stamping an authorizer's name proves only that the user typed that text in the web form. **It does NOT guarantee legal consent, authenticity, or tamper-proof provenance.** It serves solely as an advisory provenance notice for compliant media players.

## 4. Storage & Network Security Disclosures

> [!WARNING]
> **Important User Responsibilities:**

### 1. Unencrypted Local Disk Storage
All files saved in `./data/ofrendas/{UUID}/`—including `ofrenda.json`, full-resolution portrait photographs, transcribed microphone speech notes, synthesized audio, and reference voice recordings—are **stored in plaintext without filesystem encryption**.  
**Mitigation:** To protect family assets from unauthorized physical access or offline file inspection, enable your operating system's built-in full-disk encryption:
- **Windows:** BitLocker Drive Encryption
- **macOS:** FileVault
- **Linux:** LUKS (Linux Unified Key Setup)

### 2. Absence of Local Area Network (LAN) Authentication
- **Default Loopback Binding:** By default, the application binds exclusively to `127.0.0.1:8000` (loopback interface), ensuring it cannot be accessed by other devices on your local network.
- **LAN Mode (`--lan`):** If you explicitly pass `--lan` or set `ALLOW_LAN=1`, the application binds to `0.0.0.0:8000`. In LAN mode, **there are NO passwords, user logins, session tokens, or access controls.** Anyone connected to your local Wi-Fi network can view, edit, download, or delete memorials.  
**Mitigation:** Never run in LAN mode on public, guest, or untrusted Wi-Fi networks. For multi-family or shared environments, place the application behind an authenticating reverse proxy (such as Caddy or Nginx configured with HTTP Basic Authentication) or access via a private WireGuard/Tailscale VPN.

---

## 5. Data Deletion & Retention

- **Total Local Control:** User memorials, photographs, and audio recordings remain exclusively under `./data/ofrendas/`.
- **Permanent Purge on Delete:** Calling `DELETE /api/ofrendas/{id}` completely deletes the memorial's directory tree (`shutil.rmtree`). No orphaned copies, backups, or shadow files remain on disk.
